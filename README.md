# تطبيق الزيارة الإشرافية الداعمة لمراكز التطعيم

**المركز الوطني لمكافحة الأمراض (NCDC) — إدارة التطعيمات — ليبيا**
**إعداد: د. محمد علي الجرنازي** — رئيس قسم الإحصاء والمعلومات، إدارة التطعيمات

> من التفتيش إلى الإشراف الداعم: التقييم ← التحليل ← التوجيه الفني ← التصحيح الفوري ← خطة العمل ← المتابعة ← تحسّن قابل للقياس

يتكوّن النظام من جزأين يعملان على قاعدة بيانات Firebase واحدة:

| الجزء | الرابط بعد النشر | المستخدم |
|---|---|---|
| **تطبيق الهاتف** (PWA يُثبَّت على الشاشة الرئيسية ويعمل دون إنترنت) | `https://<اسم-المستخدم>.github.io/<المستودع>/` | المشرفون في الميدان |
| **منصة الإدارة** (تحليل، تقارير، تصدير) | `https://<اسم-المستخدم>.github.io/<المستودع>/admin/` | إدارة التطعيمات فقط |

---

## ما الذي يفعله النظام

**تطبيق الهاتف**
- الأداة الكاملة: 114 بنداً في 12 قسم تقييم (القسم 3 إلى 14) + معلومات الزيارة + التحضير للزيارة + مراجعة الإجراءات السابقة (القسم 15) + الحوار الداعم + الخلاصة التنفيذية والتوقيع.
- عند الإجابة بـ«لا» تُفتح لوحة **سجل النتائج وخطة العمل** للبند نفسه: تأكيد الخطورة أو تعديلها، رمز السبب الجذري (T, R, S, E, M, A, P, D, C, O)، الإجراء الفوري، الدعم المقدَّم، المسؤول، الموعد، التصعيد.
- **إشارة ضوئية مباشرة** أسفل الشاشة تحسب التصنيف العام (أحمر/برتقالي/أخضر) أثناء التعبئة وفق ملحق أ.
- ربط تلقائي بآخر زيارة للمركز واستيراد إجراءاتها غير المكتملة إلى القسم 15.
- حفظ تلقائي للمسودات، والعمل دون إنترنت: تُحفظ الزيارة وتُرسل تلقائياً عند عودة الاتصال.
- توقيع المشرف على الشاشة، وتسجيل الموقع الجغرافي (اختياري).

**منصة الإدارة**
- دخول بحساب إداري فقط (رابط خاص + صلاحية `admin`).
- تصفية حسب **البلدية** و**اسم المركز** والفترة ونوع الزيارة والتصنيف.
- لوحة مؤشرات لحظية: توزيع التصنيف العام، عدد الزيارات والمراكز، متوسط الالتزام، الملاحظات الحمراء والبرتقالية، الإجراءات المفتوحة والمتأخرة، المشاكل المتكررة بين زيارتين متتاليتين.
- رسوم بيانية: الالتزام لكل قسم، الملاحظات حسب الخطورة، الزيارات شهرياً، مقارنة البلديات، الأسباب الجذرية، التغطية ومعدل التسرب، وأكثر 10 بنود تكراراً بـ«لا».
- **تقرير مفصل لكل زيارة** مع قراءة تحليلية مكتوبة آلياً ومقارنة بالزيارة السابقة، جاهز للطباعة أو الحفظ PDF.
- **تقرير مجمّع** على مستوى البلدية/الفترة.
- **تصدير Excel** (بنفس بنية ملف التحليل: إدخال_البيانات، سجل_النتائج_CAP، …) و**CSV**.
- متابعة خطة العمل التصحيحية وتحديث «حالة المتابعة» مباشرة.

## التجربة الفورية (قبل ضبط Firebase)

بمجرد رفع المستودع يعمل النظام في **وضع التجربة**: تظهر بيانات توضيحية (منها الزيارات الثلاث من ملف Excel)، وتُحفظ أي زيارة تُرسل من الهاتف في المتصفح نفسه لتظهر في منصة الإدارة على الجهاز نفسه. للتجربة محلياً:

```bash
python3 -m http.server 8080
# ثم افتح http://localhost:8080  و  http://localhost:8080/admin/
```

## خطوات التشغيل الحقيقي

### 1) إنشاء مشروع Firebase
1. ادخل [console.firebase.google.com](https://console.firebase.google.com) ← **Add project**.
2. **Build ← Authentication ← Get started ← Email/Password ← Enable**.
3. **Build ← Firestore Database ← Create database** (اختر أقرب منطقة، مثل `europe-west`) ← ابدأ في **Production mode**.
4. **Project settings ← General ← Your apps ← Web (`</>`)** ← سجّل التطبيق وانسخ كائن `firebaseConfig`.

### 2) ربط الإعدادات
الصق القيم في الملف `js/firebase-config.js` بدلاً من `YOUR_...`. هذه القيم ليست سرية؛ الحماية الفعلية عبر قواعد الأمان في الخطوة التالية.

### 3) قواعد الأمان والفهرس
في **Firestore ← Rules** الصق محتوى `firestore.rules` واضغط **Publish**.
في **Firestore ← Indexes** أنشئ فهرساً مركّباً لمجموعة `visits`: الحقل `info.center` تصاعدي ثم `info.date` تنازلي (أو استخدم Firebase CLI: `firebase deploy --only firestore`).

### 4) إنشاء المستخدمين والأدوار
1. **Authentication ← Users ← Add user** لكل مشرف ولكل مسؤول إدارة.
2. انسخ **User UID** لكل مستخدم.
3. في **Firestore ← Start collection** أنشئ مجموعة باسم `users`، ولكل مستخدم مستنداً معرّفه = UID:

| الحقل | القيمة |
|---|---|
| `role` | `admin` لمنصة الإدارة، أو `supervisor` للمشرف الميداني |
| `name` | الاسم الذي يظهر في التطبيق والتقارير |

> حساب `admin` يستطيع أيضاً استخدام تطبيق الهاتف. حساب `supervisor` لا يستطيع دخول منصة الإدارة.

### 5) النشر على GitHub Pages
```bash
git init && git add . && git commit -m "NCDC supportive supervision app"
git branch -M main
git remote add origin https://github.com/<اسم-المستخدم>/<المستودع>.git
git push -u origin main
```
ثم في المستودع: **Settings ← Pages ← Source: Deploy from a branch ← main / (root) ← Save**.

أخيراً في Firebase: **Authentication ← Settings ← Authorized domains ← Add domain** وأضف `<اسم-المستخدم>.github.io`.

### 6) تثبيت التطبيق على الهاتف
افتح رابط التطبيق من الهاتف:
- **Android (Chrome):** القائمة ⋮ ← «تثبيت التطبيق» / «إضافة إلى الشاشة الرئيسية».
- **iPhone (Safari):** زر المشاركة ← «إضافة إلى الشاشة الرئيسية».

## رابط الإدارة الخاص

منصة الإدارة محمية بتسجيل الدخول وصلاحية `admin` في قواعد Firestore؛ لا يمكن لأي شخص قراءة البيانات دون حساب مفعّل. لإخفاء الرابط أيضاً، أعد تسمية المجلد `admin` باسم غير متوقع (مثال: `admin-ncdc-7Kq2`)، فيصبح الرابط:
`https://<اسم-المستخدم>.github.io/<المستودع>/admin-ncdc-7Kq2/`
الصفحة مُعلَّمة `noindex` فلا تظهر في محركات البحث.

## قاعدة التصنيف العام للمخاطر (ملحق أ)

| التصنيف | الشرط |
|---|---|
| 🔴 **أحمر** | ملاحظة حمراء واحدة على الأقل في أي قسم، بصرف النظر عن النسبة الإجمالية |
| 🟠 **برتقالي** | لا ملاحظات حمراء، لكن 3 ملاحظات برتقالية أو أكثر، أو نسبة التزام أي قسم أقل من 75٪، أو إجراء متأخر من زيارة سابقة |
| 🟢 **أخضر** | لا ملاحظات حمراء، أقل من 3 برتقالية، وكل الأقسام 75٪ فأكثر |

نسبة الالتزام لكل قسم = عدد «نعم» ÷ (عدد «نعم» + «لا»)؛ «لا ينطبق» لا تدخل في الحساب. مستوى خطورة كل بند هو المرجعي من الأداة ما لم يعدّله المشرف في سجل النتائج. المنطق كله في `js/scoring.js` ويستخدمه التطبيق والمنصة معاً.

```
├── firestore.rules · firestore.indexes.json · firebase.json
```

## التعديل والصيانة
- **إضافة بلديات أو مراكز:** عدّل `js/lists.js` (الحقلان مفتوحان للكتابة أيضاً).
- **تعديل بند أو خطورته:** عدّل `js/questions.js` مع الحفاظ على الكود (مثل `S5_Q01`) حتى تبقى البيانات السابقة متوافقة.
- **بعد أي تعديل:** ارفع رقم `VERSION` في `sw.js` ليُحدَّث التطبيق على الهواتف.
